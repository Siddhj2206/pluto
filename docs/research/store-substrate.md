## 1. celld: lease constants, retries, skew, `celld dev` store

**Node lease (there is one node lease per host; cell ownership records carry no TTL — a cell is takeable when its owner's node lease expires):**
- TTL: `CELLD_TTL_MS` default **10,000 ms** — `lease_ttl_ms_from_environment()` ([machine.rs#L101](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/machine.rs#L101), CLI help [cli.rs#L344](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/main/cli.rs#L344)).
- Renewal: **TTL/3** (`(spec.ttl_ms / 3).max(1)`) — [logic/lib.rs#L2340](https://github.com/denoland/celld/blob/v0.6.1/crates/logic/lib.rs#L2340) and #L2430; matches docs ([guarantees.md#self-fencing](https://github.com/denoland/celld/blob/v0.6.1/docs/guarantees.md), [README.md#L647](https://github.com/denoland/celld/blob/v0.6.1/docs/README.md#L647)).
- Fence timer is armed at **exactly `expires_ms`**; a renewal that lands at/after the prior lease's expiry fences the node ("the gap is a fence, not a hiccup") — [logic/lib.rs#L2361-L2443](https://github.com/denoland/celld/blob/v0.6.1/crates/logic/lib.rs#L2361).

**Waker:**
- Scan tick: `CELLD_WAKER_TICK_MS` default **60,000 ms** — [main.rs#L4580](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/main.rs#L4580), help [cli.rs#L366](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/main/cli.rs#L366).
- Advisory waker lease TTL = **tick × 3** (180 s at default), renewed at **TTL/3** — [dead_node_gc.rs#L100-L113](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/dead_node_gc.rs#L100).

**Retry constants (alarm path):** `RETRY_CEILING = 6`, `BACKOFF_BASE_MS = 2_000`, `MAX_BACKOFF_SHIFT = 6`; delay = `BASE << min(retry, 6)` — [alarm.rs#L11-L14](https://github.com/denoland/celld/blob/v0.6.1/crates/logic/alarm.rs#L11). Dead-node reconciliation backoff: `MAX_BACKOFF_SHIFT = 6`, counts double through 64 waker ticks — [dead_node_reconciliation.rs#L8-L16](https://github.com/denoland/celld/blob/v0.6.1/crates/logic/dead_node_reconciliation.rs#L8). Dead-owner log recovery: 1,000 ms backoff, 240 attempts, 15-min per-attempt timeout — [machine.rs#L85-L92](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/machine.rs#L85); recovery heartbeat 5 s [node_log.rs#L438](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/node_log.rs#L438); member-fate grace 3×TTL (min 20 s) [node_log.rs#L5056](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/node_log.rs#L5056).

**Clock skew:** no lease-clock margin is documented or coded. Safety is explicitly clock-independent: acks re-read the ownership record instead of comparing clocks ([guarantees.md, acknowledgement rule](https://github.com/denoland/celld/blob/v0.6.1/docs/guarantees.md)); the TLA+ model assumes "perfect shared clocks" ([testing.md#L42](https://github.com/denoland/celld/blob/v0.6.1/docs/testing.md#L42)); epoch-GC grace is skew-sensitive but "a margin for a slow unowned reader, not part of the safety argument" ([ltx_repl.rs#L1862-L1864](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/ltx_repl.rs#L1862)). The only hard skew bound is peer-auth: `CLOCK_WINDOW_MS = 30_000` (signature acceptance), replay retention 60 s ([peer_auth.rs#L23-L24](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/peer_auth.rs#L23)).

**`celld dev` local store — embedded SQLite, not S3, not a file-per-object dir:**
- State dir `PROJECT/.celld/dev` ([dev.rs#L59](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/dev.rs#L59)); bucket name `celld-dev`; database file **`objects.sqlite3`** ([dev.rs#L475-L478](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/dev.rs#L475)).
- `LocalStore` implements the `object_store` trait over one SQLite DB: WAL, `synchronous=FULL`, `busy_timeout=30 s` ([local_store.rs#L56-L81](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/local_store.rs#L56), #L210-L220).
- Conditional create/update: one `BEGIN IMMEDIATE` transaction per put; `PutMode::Create` → AlreadyExists; `PutMode::Update(etag)` → Precondition unless the stored ETag matches; ETags are integers from a `store_sequence` row ([local_store.rs#L134-L188](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/local_store.rs#L134)). This is CAS because SQLite serializes writers.
- Read-after-write: every get opens the same DB; committed writes are visible (single-writer WAL). Module comment: "SQLite supplies the cross-process transaction that a directory of files cannot" and "not a shared-filesystem production mode" ([local_store.rs#L3-L9](https://github.com/denoland/celld/blob/v0.6.1/crates/celld/local_store.rs#L3)).

## 2. SeaweedFS

- **Current stable: 4.48, published 2026-09-28** ([GitHub API releases/latest](https://api.github.com/repos/seaweedfs/seaweedfs/releases/latest)).
- **Single-node S3:** `weed server -s3` starts master + volume + filer + S3 gateway in one process ([Amazon-S3-API](https://github.com/seaweedfs/seaweedfs/wiki/Amazon-S3-API)); explicit form `weed server -dir=./data -filer -s3` ([Getting-Started](https://github.com/seaweedfs/seaweedfs/wiki/Getting-Started)); single-node production form `weed server -filer -s3 -ip=<ip>` with `-volume.max=0 -master.volumeSizeLimitMB=1024` ([Production-Setup](https://github.com/seaweedfs/seaweedfs/wiki/Production-Setup)). The wiki now recommends `weed mini -dir=./data` for single-node (auto-tuned volume size 64–1024 MB, volume port 9340, Admin UI 23646, maintenance worker) but warns its defaults may change between releases — pin a version ([Getting-Started](https://github.com/seaweedfs/seaweedfs/wiki/Getting-Started), [Quick-Start-with-weed-mini](https://github.com/seaweedfs/seaweedfs/wiki/Quick-Start-with-weed-mini)).
- **Ports:** master 9333 (gRPC 19333), volume 8080 (18080), filer 8888 (18888), S3 8333 ([Production-Setup](https://github.com/seaweedfs/seaweedfs/wiki/Production-Setup)).
- **First-host gotchas:** `weed server` default volume size ~30 GB, max 8 volumes (lower both for a small disk); auth is **allow-all anonymous until any credential is configured** (then all requests must be signed); memory index ≈20 B/file — use `-index=leveldb` to cap memory ([Production-Setup](https://github.com/seaweedfs/seaweedfs/wiki/Production-Setup), [Quick-Start-with-weed-mini](https://github.com/seaweedfs/seaweedfs/wiki/Quick-Start-with-weed-mini), [Optimization](https://github.com/seaweedfs/seaweedfs/wiki/Optimization)).
- **Conditional writes:** dedicated page [S3-Conditional-Operations](https://github.com/seaweedfs/seaweedfs/wiki/S3-Conditional-Operations). `If-None-Match: *` = create-once, `If-Match: <etag>` = CAS, `412` on failure, `If-Match` supported on DELETE. "The conditional check and the write are atomic — cluster-wide": request routed by key to the ring-owner filer and applied under its per-path lock in one `ObjectTransaction` RPC; ring changes use dual-read/warm-up ([Filer-Operation-Serialization](https://github.com/seaweedfs/seaweedfs/wiki/Filer-Operation-Serialization)).
- **Release timeline for conditionals:** 3.97 (2025-09-01) initial "conditional read and write" #7154 → 4.09 (2026-02-04) fix with versioning #8080, copy-If-Match #8053 → 4.18 (2026-04-02) "make conditional mutations atomic and AWS-compatible" #8802 + filer preconditions #8647 → 4.33 HTTP-date conditionals #9863 → 4.41 (2026-08-06) conditional `UpdateEntry` #10382, list-marker exclusivity #10496 → 4.45 (2026-08-31) missing object 404 under If-Match #10985 → 4.46 (2026-09-08) route exclusive/conditional creates to ring owner #11109 ([releases](https://github.com/seaweedfs/seaweedfs/releases)).
- **Consistency:** Replication doc states `W=N, R=1`, "all the writes are strongly consistent" ([Replication](https://github.com/seaweedfs/seaweedfs/wiki/Replication)); single-node uses one filer with local `leveldb2` ([Filer-Stores](https://github.com/seaweedfs/seaweedfs/wiki/Filer-Stores)). Caveats: multiple filers with replicated *embedded* stores are **only eventually consistent** and a load balancer "might not work as expected" ([Filer-Store-Replication](https://github.com/seaweedfs/seaweedfs/wiki/Filer-Store-Replication)); empty directories are cleaned up **asynchronously** after deletes ([Amazon-S3-API](https://github.com/seaweedfs/seaweedfs/wiki/Amazon-S3-API)); list-after-write consistency is not explicitly documented anywhere found.

## 3. Filesystem CAS primitives on Linux (for a local file-backed emulation)

- **Conditional create:** `open(path, O_CREAT|O_EXCL, ...)` is an atomic create; existing path → `EEXIST`; symlinks are not followed; on NFS it needs NFSv3+/2.6+ else use `link(2)` from a unique name — [open(2)](https://man7.org/linux/man-pages/man2/open.2.html).
- **Atomic replace:** `rename()` atomically replaces `newpath` (no missing-file window; POSIX/C11); `renameat2(RENAME_NOREPLACE)` fails `EEXIST` (kernel 3.15, glibc 2.28; FS support listed); `RENAME_EXCHANGE` atomically swaps — [rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html). (Replacing with rename is last-writer-wins unless the caller first holds a lock/CAS.)
- **flock CAS:** `flock(LOCK_EX|LOCK_NB)` is advisory, associated with the open file description (dup/fork share it; a second open of the same file is independent), no deadlock detection, does not interact with `fcntl` locks on Linux, and conversion LOCK_SH↔LOCK_EX is not atomic — so a correct CAS is lock → read → compare → write → unlock; NFS flock is emulated as fcntl whole-file locks since 2.6.12 — [flock(2)](https://man7.org/linux/man-pages/man2/flock.2.html).
- **fsync ordering:** `fsync()` flushes data + metadata but "does not necessarily ensure that the entry in the directory containing the file has also reached disk. For that an explicit fsync() on a file descriptor for the directory is also needed." — [fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html). Standard durable-replace order: write temp → fsync temp → rename → fsync directory.
- **Well-known implementations:** git creates the lock file itself with `O_CREAT|O_EXCL|O_CLOEXEC` ([tempfile.c#L141-L146](https://github.com/git/git/blob/master/tempfile.c)) and retries `EEXIST` with quadratic backoff in [lockfile.c](https://github.com/git/git/blob/master/lockfile.c); `google/renameio` documents temp-file-same-FS + fsync + rename and the atomicity-vs-durability distinction ([README](https://github.com/google/renameio)). SQLite's rollback-journal/WAL commit is the canonical "fsync before you publish" reference ([atomic commit](https://www.sqlite.org/atomiccommit.html)).

## 4. MinIO CE status, and stores the prior research missed

- **MinIO:** GitHub repo `minio/minio` is **archived** (`archived: true`, last push 2026-04-24); latest release **RELEASE.2025-10-15T17-29-55Z (2025-10-16)** ([API repo](https://api.github.com/repos/minio/minio), [releases](https://api.github.com/repos/minio/minio/releases/latest)). The conditional-write fix prior research tracked shipped 2025-09-07 (issue [#21526](https://github.com/minio/minio/issues/21526), PR [#21567](https://github.com/minio/minio/pull/21567)) — i.e. the last CE releases contain it, but the project is no longer maintained.
- **RustFS** (prior research missed this one): active Rust S3 server; conditional writes merged Aug 2025, explicitly ported from MinIO ([PR #409](https://github.com/rustfs/rustfs/pull/409)); conditional PUT/COPY cases present in its s3-tests list; compatibility matrix verified 2026-08-09 ([docs](https://docs.rustfs.com/en/reference/s3-compatibility)); went 1.0.0 on 2026-09-16, latest **1.0.1 (2026-10-03)** ([releases](https://api.github.com/repos/rustfs/rustfs/releases)). Conditional-write bugs are recent and visible: If-None-Match-on-absent-object fix Dec 2025 ([#1034](https://github.com/rustfs/rustfs/pull/1034)), multipart follow-up ([#1065](https://github.com/rustfs/rustfs/pull/1065)), duplicate-implementation issue [#1321](https://github.com/rustfs/rustfs/issues/1321).
- **Apache Ozone** (prior research missed this one): conditional PutObject/GetObject/HeadObject/CopyObject/CompleteMultipartUpload designed (HDDS-13117, accepted Jan 2026) with OM-side ETag validation in the atomic rewrite path ([design commit](https://github.com/ivandika3/ozone/commit/e0e821f), [implementation PR #9815](https://github.com/apache/ozone/pull/9815)); the author's July 2026 blog says it ships in "the upcoming 2.2 release"; **latest stable is still ozone-2.1.2 (2026-09-18)**, so no stable release carries it yet.
- **Silo** (MinIO fork) was already noted in the prior research; not re-verified here. **Garage** stays disqualified (no conditional writes, by design) per the prior research.

## Facts vs choices (short)

**Settled by facts:** celld's TTL/renewal/waker/retry numbers; no clock margin for safety (readback, not clocks); `celld dev` = SQLite `objects.sqlite3`, not S3; SeaweedFS 4.48 exists, single-node command + ports + auth default + conditional-write mechanism and its hardening timeline; MinIO archived, last release 2025-10; RustFS 1.0.1 with conditionals (young, bug history); Ozone conditionals not yet in a stable release; O_EXCL / RENAME_NOREPLACE / flock / fsync-dir semantics.

**Numbers still to choose:** pluto host-lease TTL and renewal fraction (celld: 10 s, TTL/3); pluto's clock-skew margin (celld documents none; 30 s is peer-auth only); SeaweedFS version floor (prior research said ≥4.18; latest hardening is 4.46+, current 4.48); SeaweedFS volume size/count and auth config for the first host; local-store probe constants (the four-write storage probe).
